# Supabase Auth email

Supabase sends the account emails -- confirm signup, reset password, magic link,
change email -- itself. By default they come from Supabase's shared sender,
look like Supabase, and are capped at a few an hour for the whole project. These
are the dashboard settings that send them from FirstFinder's Gmail account
instead, in the same style as the app's own email (`src/utils/email.js`).

None of this is in code: it lives in the Supabase dashboard, so after changing a
template here, paste it there again.

## 1. Custom SMTP

Authentication -> Emails -> SMTP Settings:

| Setting | Value |
| --- | --- |
| Enable custom SMTP | on |
| Host | `smtp.gmail.com` |
| Port | `465` |
| Username | the Gmail address (same as `GMAIL_USER`) |
| Password | the app password, **with no spaces** (same as `GMAIL_APP_PASSWORD`) |
| Sender email | the Gmail address |
| Sender name | `FirstFinder` |

Unlike the app's own code, the dashboard does not strip spaces from the
password. Pasted with them, every Auth email fails.

## 2. Rate limit

Authentication -> Rate Limits -> rate limit for sending emails: **100 per
hour**. This only becomes editable once custom SMTP is on.

Gmail's own limit, about 500 messages a day across Auth and app email, is the
tighter of the two: 100 an hour would exhaust it in five hours. If Gmail starts
refusing, the app's email stops cleanly ("blocked" in the logs), but signup
confirmations fail with it. Move to a sending service before signups get
anywhere near that.

## 3. Templates

Authentication -> Email Templates. For each one, set the subject and paste the
whole file as the body:

| Template | Subject | Body |
| --- | --- | --- |
| Confirm signup | Confirm your FirstFinder email | [`confirm-signup.html`](confirm-signup.html) |
| Reset password | Reset your FirstFinder password | [`reset-password.html`](reset-password.html) |
| Magic link | Your FirstFinder sign-in link | [`magic-link.html`](magic-link.html) |
| Change email address | Confirm your new FirstFinder email | [`change-email.html`](change-email.html) |

Each keeps Supabase's `{{ .ConfirmationURL }}` (and, for change email,
`{{ .Email }}` and `{{ .NewEmail }}`) exactly as written: Supabase fills them in
when it sends.

The files are generated by `node scripts/build-auth-email-templates.mjs` from
`renderEmailLayout` in `src/utils/email.js`, so the frame matches the app's own
email. Change the wording in that script and rerun it rather than hand-editing
the HTML.
